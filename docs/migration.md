# Совместимость и обновление

## Обновление gwu

Установка нового gwu-пакета не запускает WireGuard или QoS и не заменяет
локальные metadata, ключи, шаблоны и активный конфиг.

```bash
sudo apt install ./gwu_0.3.0_amd64.deb
gwu version
gwu --help
sudo wg show
```

Для следующих выпусков подставьте фактическое имя пакета.
Не запускайте wireguard init для обновления: это первичная настройка системы.
Шаблоны обновляются только явным set/reset после проверки различий.

Откат бинарника — установка заранее сохранённого предыдущего пакета.
Он не отменяет изменения данных или сети, сделанные командами приложения
после обновления. Совместимость форматов проверяйте перед откатом.
При несовместимом изменении состояния нужен отдельный план восстановления.

## Переход с gwg

Gwu заменяет прежнюю реализацию приложения, но **не является автоматическим
обновлением работающей установки gwg**.

| Было | Стало |
| --- | --- |
| Бинарник и пакет gwg | Бинарник и пакет gwu |
| gwg init | gwu wireguard init, только для новой установки |
| gwg user ... | gwu wireguard user ... |
| gwg template ... | gwu wireguard template ..., также gateway |
| gwg server show/stat | Штатная утилита wg show |
| gwg tc service/bandwidth/filter | gwu qos init/render/apply/show/down |
| Персональные TC-полосы | Только общий канал, прямого аналога нет |
| tc.service и генерируемый shell | Необязательный qos.service и Netlink |
| iptables NAT, FORWARD и source rule в hooks | nftables NAT; filter/routing отдельно |

Номера версий gwg и gwu относятся к разным пакетам: gwu 0.3.0 не означает
возможность безопасного обновления gwg 0.3.1 поверх работающей сети.

### Данные

| Старый путь gwg | Путь gwu |
| --- | --- |
| /etc/wireguard/.wg_manager/<interface>.json | /etc/wireguard/gwu/wireguard/<interface>.json |
| /etc/wireguard/.configs/<user>.json | /etc/wireguard/gwu/wireguard/clients/<user>.json |
| /etc/wireguard/users/<user>.conf | /etc/wireguard/gwu/wireguard/configs/<user>.conf |
| /etc/wireguard/.wg_manager/templates | /etc/wireguard/gwu/wireguard/templates |
| /etc/wireguard/.tc | Прямого переноса в gwu/qos нет |
| /etc/sysctl.d/90-gwg.conf | /etc/sysctl.d/90-gwu.conf для новой установки |

Это сопоставление форматов, не команда миграции. Поля WG JSON в этой версии
сохраняются, однако пути, шаблоны и жизненный цикл требуют отдельной проверки.
Рабочий `/etc/wireguard/<interface>.conf` остаётся по прежнему адресу.
Каталоги должны иметь права 0700, JSON/ключи/клиентские конфиги — 0600.

### Порядок подготовки перехода

1. Зафиксируйте текущие версии пакетов, интерфейс, формат metadata, локальные
   шаблоны и владельцев NAT/filter/routing/TC. Не выводите private keys.
2. Установите gwu без запуска init и без изменения пользователей. Старые данные
   не обнаруживаются и не переносятся автоматически.
3. Подготовьте перенос metadata и клиентских конфигов с сохранением ключей,
   адресов и статусов. Сверьте JSON с моделями и допустимыми значениями gwu.
   Не оставляйте несколько серверных JSON в одном каталоге.
4. Согласуйте hooks с реально используемыми firewall/routing rules. Копирование
   старого server template сохранит старые shell hooks; reset заменит их
   встроенными nftables hooks. Ни один вариант нельзя применять вслепую.
5. Если используется старый TC, решите судьбу персональных лимитов до перехода.
   Старый tc.service и новый qos.service не должны управлять одним интерфейсом.
   Gwu откажется захватывать старую root qdisc.
6. Переключайте управление в согласованное окно. Команды изменения пользователей
   перезапускают WG; установка пакета этого не делает.
7. Проверьте peers через wg show, подключение тестового клиента, DNS, forwarding,
   NAT и фактический QoS. Только затем прекращайте использование старого CLI.

Готовой автоматической миграции и универсального сетевого отката нет.
До переключения нужен план возврата прежних metadata, шаблонов и владельцев
сетевых правил. Установка старого пакета или повторный init этого не обеспечат.
Не удаляйте старые данные и не очищайте qdisc/ruleset для обхода несовместимости.

Пакет gwu не содержит Conflicts/Replaces для gwg, поскольку файлы пакетов
различаются. Оба CLI могут оставаться установленными, но изменения одного и
того же интерфейса должны выполняться только выбранным владельцем.
